### 1.2 설계

1. **라벨 함수를 순수 함수로 분리한다.** `harmonize.commute_label(gubun, place, other_sido, minutes, home_sido)`는 numpy·pandas 없이 테스트할 수 있다. 이 Mac에는 과학 스택이 없다(ISS-039).
   - 39≠1(통학·안함·결측) → None. v1과 같은 범위이며, 통학 라벨은 추가하지 않는다(범위 밖).
   - 40=1 → "직장은 사는 곳과 같은 읍·면·동에 있고 …"
   - 40=2이고 41이 유효한 타시도 코드 → "직장은 {시도 전체명}에 있고 …" (예: 광명 거주 + 41=11 → 서울특별시)
   - 40=2이고 41이 비어 있음 → "직장은 사는 곳과 다른 읍·면·동에 있고 …". **"같은 시도"라고 쓰지 않는다.** 41의 공란이 "같은 시도"인지 "결측"인지를 원자료로 확인하지 못했으므로, 어느 쪽이든 참인 문장만 쓴다.
   - 40이 결측이거나 알 수 없는 코드 → None. v1은 알 수 없는 코드에 빈 장소명("직장은 에 있고")을 만들 수 있었다.
   - 분 값이 없거나 0 이하 → 시간 문구를 생략한다.
2. **원자료 열 추가.** `CENSUS_P_COLS`에 `통근통학_타시도행정구역코드`를 추가한다. 열 이름은 코드집 B열 문자열 그대로다. 기존 열(`통근통학장소코드`, `통근통학_소요분수`)도 코드집 문자열과 CSV 헤더가 일치했다. 헤더가 다르면 `pd.read_csv(usecols=…)`가 ValueError로 **시끄럽게 실패**한다(조용한 누락 없음).
3. **난수 흐름 불변.** 통근 라벨은 rng를 쓰지 않는다. 따라서 같은 seed·n·floor·원자료에서 v2의 표본, 급여·소득·이념 추첨은 v1과 행 단위로 같아야 한다. 이를 `scripts/compare_bank_versions.py`로 검사한다(통근·카드·ID·provenance 외 전 필드 일치). 이 성질 덕분에 v1↔v2 paired 영향 평가(ISS-033 옵션 C)가 깨끗해진다.
4. **덮어쓰기 금지.** `build_bank.py`는 출력 파일이 이미 있으면 거부한다(`--overwrite` 명시 시에만 허용). ISSUES.md 운영 메모의 "paired 기준선 덮어쓰기 금지"를 코드로 강제하는 것이다.
5. **provenance 기록.** `commute_rule`(코드집 40·41, ISS-033)과 라이브러리 버전(python·numpy·pandas)을 남긴다. 버전 기록은 ISS-039 제안을 따른 것이다.
6. **소비처 불변.** 기존 러너·채점기는 모두 `persona_bank_*_v1.jsonl`을 경로로 고정한다(`exp012_run.py:24`, `run_t3_pilot.py:31`, `score_ab.py:108` 등). v2를 만들어도 과거 실험 재현에는 영향이 없다. v2 사용은 새 EXP 카드에서 명시적으로 선택한다.

- **(i) 의도대로 동작하는가:** 라벨 함수는 단위 검사로 확인했다. **bank.py 경로 전체(판다스 행 → 라벨)는 이 Mac에서 실행하지 못했다**(numpy·pandas·원자료 부재). 재생성 시점에 확인해야 한다.

### 3.4 판정과 남은 일

- **판정: A1 완료(코드 + 산출물 + 교차모델 검토 반영).** 정정된 v2 파일은 만들었지만 아직 어떤 실험에도 투입하지 않았다. v1을 쓴 과거 실험(EXP-004/005/007/012)의 수치는 바뀌지 않는다. 오염 크기는 영향 평가 실험(ISS-033 옵션 C, EXP 카드 선행)으로만 알 수 있다.
- **커밋 주의(ISS-034):** v2 파일은 v1과 같은 MDIS 센서스 레코드 기반 개인 단위 파생자료다. 원격 저장소가 public인 동안에는 커밋·푸시하지 않는다. 비공개 전환 후 커밋 여부를 정한다.
- **A2 재빌드 체크리스트(ISS-039 이관 후):** ① CSV 헤더에 41번 열이 있는지 확인 ② 40×41 교차표로 D1·D2 가정 확인(40=1인데 41이 있는 행, 41=거주 시도인 행) ③ `build_bank.py --tag v3 --id-tag v1` 후 `compare_bank_versions.py … v1 v3` ④ 마진 검증(`validate_bank.py`)은 **EXP 카드 선행**(Codex #7) ⑤ load_pool→build_bank 통합 검사 추가.
- **범위 밖:** ISS-033 §2 가구 내 소득 비일관(옵션 D, 난수 흐름 변경)은 이번 변경에 포함하지 않았다.
