# 민심테스트와 운영 규칙

작성: 2026-09-22. 범위: 저장소 HEAD `2e4f3d6`의 `민심테스트/` 전체 소스·질문·집계보고서, ISS-027~030/EXP-014~017 및 9월 감사, DESIGN_SOUL, DECIDED 이슈. 연구 코드·원자료 수정·모델 호출·캐시 재채점·신규 성능 지표 산출 없음. 아래 실험 수치는 기존 카드·보관 결과에서 인용했고 이번에 인간 정확도나 원응답을 재검증하지 않았다. 웹 동작은 소스 확인이며 이번 조사에서 실제 브라우저 QA는 하지 않았다. 외부 URL의 현 가용성도 확인하지 않았다.

## 1. 현재 상태를 가장 정확히 표현하는 문장

민심테스트는 IDEA 연구에서 파생된 **소비자용 정적 체험 웹 + 이미 끝난 모델 실험 집계 조회 화면**이다. 임의 질문을 입력하자마자 1,200명에게 질의하는 실시간 서비스는 아니다. 연구 엔진과 브라우저 사이에 작업 큐·API·서버 연결이 없다. 사용자가 보는 숫자는 (a) UX용으로 사람이 작성한 여섯 fixture 또는 (b) 2026-09-14에 미리 실행한 실험의 확률 평균이다.

연구의 단위도 구분해야 한다. MDIS 기반 전국·광명 뱅크와 달리 민심테스트는 EXP-009의 **같은 KGSS 응답자 1,200명**(2018·2021·2023·2025년 각 300명)을 기반으로 하고 전국 대표 가중치를 적용하지 않는다. 실제 사람의 현재 투표 비율, 한국 국민의 여론, 개인 마음의 정답이라고 해석하면 안 된다.

## 2. 소비자 경험이 만들어진 과정

1. **2026-09-11 독립 소비자 UI**: 사용자 요청으로 연구 정확도 리포트와 분리한 소셜 게임 시제품을 만들었다. 처음 예측하고 결과·점수·의견을 비교하는 흐름. 임의 질문에는 미리 정한 결과를 돌려쓰지 않고 로컬 비공개 초안만 저장한다. ISS-027은 이 범위를 ANALYZED로 기록한다.
2. **게임형 디자인 수정**: 설명 과밀 피드백에 따라 세대/성별·이유·근거를 접기로 내리고 핵심 참여 흐름을 앞세웠다. 이후 보라·코랄 장식의 가독성 문제로 Kalshi를 참고한 흰 배경·진한 본문·얇은 경계·정렬된 선택지로 다시 수정했다. 이는 소비자 화면 변경이지 연구 리포트의 OWID 디자인 입장 폐기가 아니다.
3. **홈 자유 질문을 주 진입점으로**: 8~180자 입력, Enter 제출·Shift+Enter 줄바꿈·한글 IME 보호. 대상·조건·선택지를 직접 수정하는 2단계 모달로 전달한다. AI 정규화는 아직 연결되지 않았다.
4. **홈 전체 테마 연속 탐색**: 테마 선택 버튼 대신 전체 질문을 스크롤해서 본다. 데스크톱 2열 질문 카드+오른쪽 인기/최신 목록; 1,100px 이하 보조 목록을 아래로, 700px 이하 1열. 별도 탐색 화면은 검색·필터·정렬 유지.
5. **2026-09-12 파일럿 질문 6개 준비**: 부모 주거지원, 가사분담, AI 채점, 주4일제, 퇴근 후 연락, 가족 정의. 각각 두 조건·유보 포함 6선택지. UI 예시 6개와 이 실험 질문 6개는 동일 목록이 아니다.
6. **2026-09-14 상세 프로필 복원 및 실제 실행**: 사용자가 원래 ID 전원의 상세 설문을 넣도록 정정했다. 원자료를 확보한 뒤 비어 있던 2021/2025년 600명의 full_lines를 복원하고 나머지 600명은 원문 일치를 검증했다. 부모지원 70%→성별 미지정 동일시간 가사→성별 지정 소득차이 실험으로 확대했다.
7. **실행 결과를 별도 컴포넌트로 연결**: 기존 양자택일 fixture에 숫자만 끼우지 않고 6개 분포·중립·유보를 보존하는 [research.js](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/research.js)/[research-data.js](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/research-data.js)를 추가했다. 예시 점수·범위·가짜 방문자 수를 실제 실행 결과에 섞지 않는다.
8. **2026-09-16 배포 기록**: ISS-029에 Sites version 10, 소스 commit `592ce86e2c6bc5bb5d3360c0c78598259a750b06`, deployment `appgdep_6aaa2043c9248191b7e09fd6492c0884` 성공 기록. 주소 `https://minsim-test.wodnjsv81.chatgpt.site`. 이번 조사에서 live 확인은 하지 않았다.

## 3. 브라우저가 실제로 수행하는 일

[index.html](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/index.html) → ES module [app.js](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/app.js) → [research.js](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/research.js) → 집계 상수 [research-data.js](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/research-data.js). 빌드 프레임워크나 백엔드가 없어 정적 HTTP 서버로 제공한다. 파일을 직접 여는 대신 모듈을 지원하는 HTTP 제공이 필요하다.

- 해시 라우터: `#/`, `#/feed`, `#/saved`, `#/records`, `#/predict/{id}`, `#/result/{id}`.
- 데이터: `questions=[...researchQuestions, ...6 fixture]`. 실제 연구 결과 2개와 UI 예시 6개를 합쳐 8개 질문 레코드로 다룬다.
- 예시 6개: 주4일제, 축의금, AI 과제 채점, 월급 인상 vs 주4일제, 콘서트 VIP 경매, 현금 없는 매장. 비율·범위·참여 수·성/연령 수치·양측 이유 모두 [app.js](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/app.js) 상수다.
- 예시 질문에서는 최초 예측을 고정하고 `max(0,100−2×abs(내예측−fixture비율))` 체험 점수를 준다. 이는 사용자 연구능력 또는 모델 정확도가 아니다.
- 예시 방문자 투표는 고정 예시 분포+브라우저 1표이며 선택을 바꿀 수 있다. 서버에 전송하지 않는다.
- 실제 실험 질문은 예측 입력 없이 결과를 바로 연다. 부모는 70% 단일 조건, 소득 가사는 E/H30/W30 조건 선택이 가능하다. 개인 의견은 조건별 키 `questionId:condition`으로 따로 저장한다.
- 실제 결과는 전체 6선택지, 소득조건 차이, 성/연령 집단 분모와 6선택지 표, 입력과 검증 한계를 제공한다. 이전 익명 A/B Luna 가사 결과는 별도 접기로만 표시하고 GPT-5.5 성별 지정 결과와 소득효과 비교를 금지한다.
- 실제 실험의 이유·의견 문장은 생성하지 않았으므로 화면에서도 발명하지 않는다.
- `localStorage` 키는 `minsim-demo-v1`. 기록·투표·책갈피·질문 초안을 저장한다. 로그인·회원DB·기기 간 동기화·서버 방문자 집계가 없다.
- 임의 질문은 `title/type/a/b/condition/population`을 저장하는 비공개 초안. 질문 정규화, 실행 승인, 모델 작업 ID, 대기/실패/재시도 API가 모두 후속 과제다.
- 예시에는 1080×1080 PNG 내보내기, 실제 실행에는 결과 링크 복사만 제공한다.
- WebMCP를 지원하는 브라우저에서는 `list_demo_questions`, `open_prediction_question` 두 도구를 등록한다. 이것은 브라우저 탐색 인터페이스이지 모델 백엔드가 아니다.

실제 연구 경로: `#/result/parent-support-70`(EXP-014), `#/result/housework-income-30`(EXP-017). [research-data.js](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/web/dist/research-data.js)에는 2개 결과와 이전 EXP-015 집계만 있고 개인 ID·원설문·raw는 공개 웹에 넣지 않았다는 기존 감사 기록이 있다.

## 4. 실험 처리 구조

### 4.1 입력 복원

[minsim_restore_profiles.py](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/scripts/minsim_restore_profiles.py)는 registry의 `kgss_cum_2003_2025`, `minsim_original_personas`, `minsim_legacy_exclusions`를 사용한다. [scripts/exp009_kr_prep.py](../../scripts/exp009_kr_prep.py)의 검토된 순수 helper/상수만 AST로 뽑아 재사용하고 원본 스크립트 top-level I/O를 실행하지 않는다.

- 기존 PID 1,200개와 조사시점 인구정보를 확인한다.
- 연도별 유효 응답률 30% 이상인 변수 중 관리변수·인구정보 중복·기존 제외문항·정치관련 변수를 제외한 FULL pool에서 실제 응답만 채운다.
- 이미 FULL이 있던 600명은 완전히 일치하는지 확인한다. 관리용 가구번호는 최종 입력에서 제외한다.
- 한 사람당 실제 상세 응답 214~361개. 이는 원자료의 모든 변수라는 뜻이 아니다.
- 나이·직업·가족을 2026년 현재 상황으로 업데이트하지 않는다. 과거 응답자 기반 가상 판단이다.
- 원자료·원페르소나·복원본·legacy prep 해시 및 동일 ID/원본 불변을 기록한다.
- 출력: 로컬 `data/minsim/luna_parent70/personas_full.jsonl`, profile_variables.json, restore_checks.json. 이 개인별 입력은 Git 보관본에 없다.

### 4.2 생성

공통 러너 [minsim_luna_run.py](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/scripts/minsim_luna_run.py)는 이름과 달리 GPT-5.5도 지원한다.

- `engine.registry.data_dir()/resolve(verify=True)`로 데이터 경로·해시 검증. `IDEA_DATA_DIR` 환경변수 지원.
- 사람마다 독립 ephemeral Codex 세션, effort low, k=1 분포발화. 부모는 SA/A/N/D/SD/U, 가사는 P0/P25/P50/P75/P100/U.
- BASE 지시는 실제 개인 기록만 근거로 가상 선택확률을 추정하고 누락 개인정보·전국 평균을 발명하지 말라는 것. 개별 실제 기록은 x로 투입하되 집계 P(y)는 넣지 않는다.
- 선택지는 PID로 결정되는 순서로 섞고 동일 PID는 조건 간 같은 순서를 유지한다. 이것은 표시 순서 재현성이며 모델 난수 결정론을 뜻하지 않는다.
- `openai_codex` SDK/로컬 Codex CLI의 ChatGPT 구독 로그인 강제. 웹·쉘·앱·MCP·스킬 등 도구를 꺼 놓고 runtime model/provider, reroute·unexpected item을 검사한다. 유료 API키 경로는 사용하지 않았다는 카드 기록이다.
- 유한한 숫자, [0,1], 정확한 키 집합, 합오차≤1e-6, 중복 JSON키 거부. 음수 클립·자동정규화·누락키 보충 없음.
- 캐시키는 BASE+모델+effort+개별 프롬프트+schema 해시. 재개할 때 이전 cache_key·environment manifest 일치를 요구한다.
- `raw.jsonl`에 최초 유효 응답·원문·스트림 items·토큰·thread ID·runtime·소요시간·실패를 보관한다. 세션 실행 lock 및 실패 제한이 있다.
- 동시성 확장 수치는 실험 관측치이며 공식 서비스 허용한도가 아니다.
- 순수 채팅 API와 동일한 환경은 아니다. 전역 `~/.codex/AGENTS.md`는 runtime에 포함됐고 모델 alias의 불변 snapshot·temperature·모델 seed를 확보하지 못했다.
- 이 SDK 실행 경로는 연구용 배치 생성이며 웹 사용자의 자유 질문과 연결되지 않는다.

### 4.3 paired 소득 드라이버와 MDE

[minsim_income_run.py](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/scripts/minsim_income_run.py)는 동일한 64명 첫 블록, 이후 128명 블록에 대해 조건 순서를 블록 seed로 섞어 조건별 러너를 순차 실행한다. 각 러너 내부가 64/128 병렬이므로 총 동시성을 제한한다. 이전 블록 유효 ID를 확인하고 미완료·재시도 소진이면 다음 블록으로 넘어가지 않는다.

Luna는 E/H10/H30/W10/W30(6,000유효 목표), GPT-5.5는 E/H30/W30(3,600유효 목표). GPT-5.5에서 Luna 응답을 섞거나 기존 익명 A/B baseline을 재사용하지 않는다.

[minsim_income_mde.py](../../%EB%AF%BC%EC%8B%AC%ED%85%8C%EC%8A%A4%ED%8A%B8/scripts/minsim_income_mde.py)는 EXP-009 캐시와 phase0 캐시를 기획 proxy로 읽어 SD 및 기획 MDE를 계산한다. 현재 질문/모델의 검정력을 직접 검증한 값은 아니다. NUKPLT18 A1과 B1이 반대 의미라는 중간 감사로 focal을 A1/B3에 정렬했다. 주기획은 애초 SD(delta) 상한1을 사용했으므로 전체 목표 MDE 판정은 바뀌지 않았다.

### 4.4 집계와 표시

## 6. 운영·방법론 정본의 주요 규칙

DECIDED는 도입 방향의 인간 결정이며 구현/검증 완료와 다르다. 역사 카드의 ‘미착수’와 나중 구현 상태도 구분한다.

- **ISS-001**: 이념·정당 마진을 답 힌트로 프롬프트에 주입하지 않고 구성비/사후가중 경로. 독립 시점·출처, G9 비LLM baseline을 병기하고 정당ID 유무의 민감도 보존을 검증한다.
- **ISS-002**: 데이터 registry→loader→canonical schema, IDEA_DATA_DIR, 행정표준코드 조인, 해시·전국 합계 골든 검증. 카드의 yaml 제안과 실제 json 구현을 혼동하지 않는다.
- **ISS-003**: x(개인·시나리오 사실)는 허용, 응답 집계 P(y)와 행동 지시는 금지. 회색지대는 어블레이션으로 정확도·하위집단·델타·placebo를 확인한다.
- **ISS-005**: PPI, 저자유도 보정, partial pooling, baseline+delta 분리. LOEO는 2~3이질 선거로 모델/하이퍼파라미터 선택 금지, 기술적 전이 보고 전용. 지선은 영구 제외하여 봉인한다. 선거→광명 정책 전이는 미검증.
- **ISS-009**: 지선은 사전등록 commit 동결 후 1회 봉인 백테스트. 후보 유효득표/조사 DK포함의 estimand를 분리하고 정보시점을 고정한다. 21대 대선 개발셋의 반복채점은 허용되지만 대외 성과로 인용 불가.
- **ISS-010**: T2는 MDIS 2% 직접 샘플링 우선(IPF fallback), KGSS 조건부 성향 분포와 희소셀 fallback. 이념 라벨 경로는 인간 이중코딩·κ/오분류행렬 검증, 마진 불확실성 전파가 규칙. 코드 일부 작동만으로 이 전체 규칙이 검증됐다고 말하면 안 된다.
- **ISS-011**: paired는 동일 persona·동일k의 인물별 확률 차분. seed가 동일 난수를 보장한다는 주장 금지. raw+sha256가 재현 정본. 조건 비교 전 MDE 표 필수, 동일 인물의 조건별 선택지 순서 동일.
- **ISS-012**: cutoff<event date, 위반시 MEMORIZATION_RISK 라벨·백테스트 성과 인용 금지. 역사 고정모델은 gpt-4o-mini-2024-07-18이며 후속 모델은 실험별 적합성 감사 필요. 최신 구독모델의 가상 사회질문 실행을 과거 선거 백테스트 성능으로 재활용하면 안 된다.

## 7. 디자인과 연구 증거의 경계
