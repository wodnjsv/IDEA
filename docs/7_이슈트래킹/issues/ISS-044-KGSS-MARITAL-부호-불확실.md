# ISS-044: KGSS MARITAL 코드 방향 불확실 — 도너 풀 계측(ISS-025)의 혼인 셀 반전 가능성

- **상태**: OPEN
- **유형**: 데이터 | 코드
- **심각도**: P2 (DECIDED ISS-025의 근거 수치에 걸림. EXP-019에서 x 동결 전에 해결)
- **발견**: 2026-09-26. EXP-019 설계 중 발견했고(`EXP-019:136`, P3·P19), 주 루프가 코드를 대조해 확인했다. Claude 단일 모델 결과다.
- **관련**: ISS-025(`ISS-025:49-55`), `scripts/exp011_pre_donor_pool.py:31,40`, `src/engine/harmonize.py:117`, EXP-011, EXP-019 D10, ISS-039

## 문제 (Issue)
- **KGSS 쪽**: `exp011_pre_donor_pool.py:31`은 `mar = "기혼" if r.get("MARITAL") == 1 else "비혼"`이다. KGSS MARITAL 코드 1을 '기혼'으로 간주한다.
- **뱅크(센서스) 쪽**: `:40`은 `"기혼" if s["marital"] == "배우자 있음"`이다. 센서스 코드집상 1 = 미혼, 2 = 배우자 있음이다(`harmonize.py:117`).
- **값 라벨 부재**: 저장소에 KGSS MARITAL 값 라벨이 없다. `data/kgss_item_inventory.csv:4`에는 변수 라벨 '응답자 혼인상태'뿐이고, `kgss_item_entropy.csv`는 범주 수를 6으로 적었다. 따라서 KGSS 코드 1이 '미혼'인지 '기혼'인지 확인되지 않았다.
- **영향**: KGSS 1이 '미혼'이면 도너 풀 사다리의 최세밀 수준(성×연령10×학력×수도권×혼인, 106셀)에서 **혼인 키가 뒤집힌 채 매칭**된다. 그러면 ISS-025 표의 해당 행(중앙값 59명, <30명 35.6%, 뼈대/도너 2.09)이 틀린다. 거친 수준 L2~L4는 혼인을 쓰지 않으므로 영향이 없다. [추측] GSS 전통 부호는 1 = married지만, KGSS의 부호는 원자료 메타로 확인해야 한다.
