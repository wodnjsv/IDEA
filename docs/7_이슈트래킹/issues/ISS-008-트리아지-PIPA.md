# ISS-008: 제보 트리아지의 개인정보(PIPA) 처리 — 목적 제한·민감정보

- **상태**: ANALYZED (2026-07-18 상태 정정 — 완화 설계·게이트가 정리된 상태이므로 상태기계 정의상 ANALYZED; 결정은 법적 검토 결과 대기)
- **유형**: 법률·윤리
- **심각도**: P1 (트리아지 웨지 착수 전 필수 해소)
- **발견**: 2026-07-05, design doc 적대적 리뷰 (Completeness #1 + 2차 리뷰 sub-gap)
- **관련**: design doc(~/.gstack/projects/wodnjsv-IDEA/parkj-main-design-20260705-151404.md) §Constraints

## 문제
제보 트리아지 웨지는 시민 제보(이름·주소·민원 내용이 섞인 자유텍스트 = 개인정보)를 LLM 파이프라인에 넣는다. 세 층의 법적 문제: (1) **PII 처리** 일반, (2) **목적 제한** — 제보는 민원 처리 목적으로 제출된 것이라 AI 여론 시뮬레이션은 다른 목적(가명화만으로 불충분 가능), (3) **민감정보(PIPA §23)** — 정치적 견해는 민감정보라 별도 법적 근거/동의 필요.

## 분석
설계된 완화(구현 전): 인테이크 즉시 가명화/최소화, 원문 PII는 LLM 입력 금지, 의회와 위수탁 계약, 개인정보처리자 확정(의회 vs 우리). 모듈 경계: `triage/`를 `engine/`과 분리해 blast radius 격리(eng review P2). 윤리 가드레일: "소수, 무시" 벌거벗은 라벨 금지, 저지지 견해도 화이트박스 이유와 함께 표면화.

미해소: 목적 제한과 §23은 가명화로 안 풀림 — 수탁 구조가 성립하려면 목적이 의회 사무 범위 내여야 하고, 정치적 견해 추론엔 별도 근거 필요. **법적 검토(전문가 or 최소한 공식 가이드라인 대조) 없이는 실제 제보 데이터 수령 불가.**

## 결정
미결. W1-2 법적 검토가 선행 조건(design doc에 명시됨). 검토 전까지 실제 제보 데이터로 파일럿 금지 — 필요 시 합성/공개 민원 데이터로 파이프라인만 개발.

- [ ] triage/ 모듈 분리 골격 + 가명화 인테이크(T5)
