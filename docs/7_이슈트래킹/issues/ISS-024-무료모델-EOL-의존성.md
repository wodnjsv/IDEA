# ISS-024: 무료 호스팅 모델의 서비스 종료(EOL) — 실험 재현성의 외부 의존성 리스크

- **상태**: OPEN
- **유형**: 데이터 | 설계
- **심각도**: P2
- **발견**: 2026-08-30, EXP-009 스모크(410 Gone)
- **관련**: EXP-008(잔여 스윕 강제 종료) · EXP-009 개정 3 · ISS-012(컷오프 게이트)

## 문제 (Issue)

NVIDIA 무료 호스팅에서 llama 3.1/3.3 계열 전체가 2026-08-26 일괄 EOL — 실측 영향 2건:
1. EXP-008 K0/K5 잔여 스윕이 82/83%에서 강제 종료(마지막 2,000행 중 1,400행 410 에러). 동일 모델 완결 불가·타 모델 혼합 금지 → 그 시점 표본으로 최종화.
2. EXP-009 등록 모델(llama-3.1-70b) 소멸 → 직계 확장(llama-3.2-90b-vision)으로 개정 교체.

무료 티어는 사전 공지 감지 경로가 없고, 장기 실험(2일+) 중 EOL이면 데이터가 두 모델에 걸쳐 오염될 수 있다. 처리량 상한(~9-30콜/분, 시간대 변동)도 계획 불확실성.

### 추기 (2026-09-23, 전체 저장소 팔로업 리뷰)
- 출처: 2026-09-23, 전체 저장소 팔로업 리뷰(Claude 단일 모델 워크플로 — 읽기 전용 교차대조, 교차모델 검토 전). 기준 HEAD `33c73c5`.
- 범위: 정적 소스와 저장 프로브 기록만 대조했다. 외부 API 호출(가용성 프로브 포함)은 하지 않았다. 상태는 OPEN을 유지한다.

1. **공통 기본 모델이 EOL 모델이다.**
   - `src/engine/llm_client.py:77`의 `DEFAULT_MODEL = "llama-3.3-70b"`는 `0f32580` 이후 바뀌지 않았다.
   - `add_backend_args`의 기본 provider는 `nvidia`(:273)이고, `resolve_backend`(:286)는 `--model`이 없으면 이 기본값을 쓴다. 따라서 이를 쓰는 러너(`scripts/run_ab_cards.py:56,61`, `scripts/run_t3_pilot.py:63,69`)를 `--model` 없이 실행하면 EOL 엔드포인트로 발주된다.
   - 컷오프 게이트는 통과하므로 실행이 막히지 않는다. 예상 결과는 조용한 혼합이 아니라 410 오류다 [추측 — 호출로 확인하지 않음].
   - EXP-009:76은 3.3-70b를 포함한 llama 3.1/3.3 전 계열 소멸을 기록했다.
   - 개별 러너의 `--model` 기본값도 EOL 모델이다: `scripts/exp008_run.py:57`, `scripts/exp009_us_run.py:102`, `scripts/probe_knowledge.py:30`(모두 llama-3.1-70b).
2. **레지스트리 EOL 주석이 불완전하다.** 구현 절의 "모델 레지스트리에 EOL 주석"은 부분적으로만 사실이다.
   - EOL 주석은 `llm_client.py:55,57`의 llama-3.1-70b·3.1-8b에만 있다.
   - llama-3.3-70b(:50-51)에는 "비추론·안정 호스팅"이 남아 있고, llama-3.1-405b(:52-53)에는 EOL 표기가 없다.
   - gemma-3-27b(:61-62)는 "한국어 후보 1순위"로 적혀 있지만, `data/t3/nvidia_probe.json`에는 410 "end of life on 2026-05-12"로 기록돼 있다.
   - 저장 기록 기준으로 `PROBE_SHORTLIST`(:75-76) 7종은 모두 404/410이거나 08-26 EOL 대상이다.
3. **옵션 A·B·D 이행 현황.**
   - `src/`·`scripts/`의 .py에는 410/Gone 처리, 연속 오류 정지, 모델 태그 검증 코드가 없다(grep 0건).
   - 옵션 A 성격의 발사 전 스모크 게이트는 실험별로만 있다. 예: `scripts/exp010_us_chain.ps1:25,30`은 스모크 성공 6건 이상일 때만 본런으로 넘어간다(Windows 전용, ISS-039).
   - 옵션 D(카드별 대체 규정)는 적용되지 않았다. 다음 두 실험은 llama-3.2-90b에 의존하지만, 두 카드 모두 모델 소멸 시 대체 규정이나 ISS-024 참조가 없다(grep 0건).
     - EXP-011 v2.1의 C1/C2 암: 32,400콜과 B4 어블레이션 16,200콜(EXP-011:47-48,70).
     - EXP-013의 llama 조건: 600콜(EXP-013:16,36).
   - llama-3.2-90b의 현재 가용성은 외부 호출을 하지 않아 확인하지 못했다 [미검증].
4. **영향 목록에서 빠진 것.**
   - 문제 절(:11-13)은 EXP-008·009만 들고 EXP-006을 빠뜨렸다. EXP-006은 원 확정 모델 llama-3.1-70b가 EOL이라 원 규격으로 완결할 수 없는데, 상태는 여전히 "사전 등록"이다(EXP-006:3, ISSUES.md:55).
