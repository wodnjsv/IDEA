# ISS-009: 검증 무결성 — "지선 홀드아웃"은 홀드아웃이 아니다 + 채점 estimand 미정의

- **상태**: DECIDED
- **유형**: 방법론
- **심각도**: P1 (검증 서사 전체의 타당성)
- **발견**: 2026-07-18, 적대적 감사(방법론 레드팀 F2·F8)
- **관련**: ISS-005, 구현계획_v1(W1-2), 백테스트 문서 §6

## 문제
(1) 9회 지선(2026-06-03) 결과는 이미 공개됐고 엔진은 미착수 — W11 채점은 정답을 아는 팀이 정답 공개 후 만든 파이프라인으로 수행된다. 홀드아웃의 전제("시스템이 정답 확정 전에 동결됨")가 성립하지 않고, 사전등록·봉인 절차가 어디에도 없어 설계 반복 전 과정에 무의식적 누출(forking paths)이 열려 있다. (2) 채점 자체의 estimand가 미정의: 어느 갤럽 wave와(부동층 비율은 wave마다 다름, 공표금지 6일 갭), DK를 어떻게 배분해(DK-제외 비교는 MCAR 가정 암묵 채택), 어느 모집단(투표자 vs 전체 유권자)·시점과 비교하는지가 없어 사후에 유리한 비교를 고를 수 있다.

## 분석
검증의 타당성은 (모집단, 시점, 모드, 하우스) 4축 고정 + 시간 무결성에서 온다. 진짜 홀드아웃은 미래 사건뿐이다.

## 결정 (2026-07-18, 대표 승인)
1. **명칭 강등**: 지선 채점은 "홀드아웃"이 아니라 **"봉인 백테스트"**. 실행 전 전체 config(프롬프트 커밋해시·페르소나 스냅샷·보정 모수·채점 규칙)를 **사전등록 커밋으로 동결**, 결과 확인 후 수정 금지(수정 시 시도 횟수 공개).
2. **채점 프로토콜 사전등록**(W1-2 산출물): 트랙①(개표) = likely-voter 필터 + 명시된 DK 배분 규칙 → 득표율 비교. 트랙②(조사) = 특정 wave를 field date까지 지정(공표금지 직전 마지막 갤럽) + 시뮬 정보 주입 시점을 그 date로 고정 → DK-포함 분포 비교. 하우스 오차 밴드(±3.1%p+)를 허용오차에 반영.
3. **진짜 홀드아웃 주장은 미래 사건**(차기 재보선·신규 갤럽 wave)으로만.

## 구현

- [ ] T4 하네스에 봉인 config 해시 기록 필드
