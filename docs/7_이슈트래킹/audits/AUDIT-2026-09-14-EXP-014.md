# AUDIT — EXP-014 부모 주거지원 70% 조건

- 날짜: 2026-09-14
- 독립 검토자: design_audit
- 상태: **최종 로컬 캐시·집계·보고서 검증 통과 — 모델 정확도 및 방법론 게이트 검증은 아님**
- 관련: EXP-014, ISS-028, ISS-003, ISS-014, ISS-023
- 범위: `민심테스트/scripts/minsim_restore_profiles.py`, `민심테스트/scripts/minsim_luna_run.py`, `민심테스트/scripts/minsim_luna_report.py`
- 이 감사에서 LLM 호출은 실행하지 않았으며, 개인별 원자료 응답은 출력하지 않았다. 3절은 임시 디렉터리의 합성 데이터 테스트이며, 6절은 실행 완료 후 실제 로컬 캐시를 독립 대조한 결과다.

## 1. 착수 전 설계 감사

동일한 기존 1,200개 PID의 상세 응답 복원, 원본 EXP-009 캐시 보존, parent_support 조건 B 한 가지에 대한 dist-only 실행을 검토했다. 단일 조건이므로 조건 차분/MDE는 비해당이며, 현재 국민 대표성·인간 응답 정확도·지원금 변화의 인과효과를 주장하지 않는 범위다.

주요 요구 사항:

- 기존 prep의 top-level 실행은 원본 파일을 덮어쓰므로 순수 함수만 추출한다.
- 원자료 해시, 동일 PID·인구정보, 기존 FULL 응답의 일치를 검사한다. FULL은 연도별 유효응답률 30% 이상 등 기존 변수 선정 규칙에 따른 상세 응답이며, 모든 원자료 변수를 의미하지 않는다.
- 인물별 새 세션을 사용하고, 6개 확률의 키·유한값·범위·합계를 검사한다. 최빈 선택으로 변환하지 않는다.
- ChatGPT 인증 및 요청 모델을 확인하고 API 키/NVIDIA로 대체하지 않는다.
- 전역 지침 등 환경 유입과 모델 메타데이터의 한계를 기록한다. 재현성 미확보를 숨기지 않는다.

## 2. 실행 러너 중간 검토

첫 검토에서 발견한 모델 반환정보 누락, 마지막 유효 캐시 선택, 중복 JSON 키 수용, 인증·모델 오류의 정지 누락, 실패 요청의 중간 이벤트 유실을 부모 에이전트에게 전달했다.

후속 소스에서 다음 수정을 확인했다:

- low-level 시작 응답의 model/provider 보존 및 검사
- stream item 검사와 사용량 누적, 모델 reroute 발견 시 오류 처리
- 최초 유효 응답 선택, 이전 시도의 cache_key 대조, 프로세스 잠금
- 중복 JSON 키 거부, 유한한 0–1 확률 및 합계 검사
- fatal 오류 또는 연속 오류에 대한 신규 발주 중단
- 전역 AGENTS 지침 해시·SDK/CLI 버전 등을 포함한 환경 manifest 및 재실행 대조

전역 Codex AGENTS 지침은 포함된 환경이다. 순수한 지침 없는 채팅 환경으로 기술하면 안 된다. 초기 108건은 시작 반환 모델/provider 기록이 없어 요청 모델만 확인된 상태로 구분한다. 이를 삭제·재생성해서 관측된 응답을 대체하지 않는다. 실제 전체 캐시의 해당 건수와 환경 일치 여부는 최종 검증에서 별도 확인해야 한다.

## 3. 집계 코드 합성 테스트

`minsim_luna_report.py`의 main 함수와 실제 확률 validator를 AST로 추출하여, SDK나 LLM을 실행하지 않고 임시 디렉터리의 합성 입력으로 검사했다. 합성 입력은 4개 연도·2개 성별·5개 연령 집단에 걸친 1,200개 고유 PID와 고유 thread ID로 구성했다.

| 검사 | 실행 증거 | 판정 |
|---|---|---|
| 미완료 보고 차단 | 1,199개 유효 응답 입력 시 AssertionError, summary 파일 미생성 | 통과 |
| 확률 평균 및 집단 분모 | 동일 확률 벡터 1,200개에서 동의 확률 평균 0.5; 성별·연령별 n 합계 각각 1,200 | 통과 |
| 최초 유효 응답 유지 | 첫 PID의 서로 다른 두 번째 유효 응답 추가 후 평균 0.5 유지, duplicates_valid=1 | 통과 |
| 사용량 null | 한 응답에 usage=null 지정 시 AttributeError, summary 미생성 | 수정 필요 |
| 이질 캐시 검출 | 한 유효 응답의 cache_key와 model을 다른 값으로 바꿔도 보고서 생성 | 수정 필요 |

위 수치는 집계 코드 테스트용으로 만든 값이며, EXP-014 실제 결과나 모델 성능이 아니다.

## 4. 집계 코드 발견사항

### R1 — 사용량 누락 보고 경로가 null에서 실패함 [P2]

검토 시점 `minsim_luna_report.py:39`의 `r.get("usage", {}).get(...)`는 키가 존재하고 값이 null이면 실패한다. 초기 러너는 usage를 명시적으로 null로 저장할 수 있었으므로 실제 캐시 형식에서 가능한 상태다. `usage`와 필요 시 `total`을 빈 매핑으로 처리하고, 누락 건수는 그대로 보고해야 한다. 유효 확률 응답을 사용량 누락 때문에 제거해서는 안 된다.

### R2 — 집계 단계가 현재 실험과의 캐시 정합성을 독립 검증하지 않음 [P2]

검토 시점 `minsim_luna_report.py:18–23`은 valid 플래그와 JSON 분포만 검사한다. 현재 문항·프로필로 재계산한 cache_key, 요청 모델, 존재하는 runtime의 model/provider, persona의 조사 연도, 모델 reroute·예상 밖 도구 item 여부를 함께 확인해야 한다. 초기 108건의 runtime 미기록은 문서화된 예외로 허용하되, runtime이 존재하면서 불일치하는 행을 같은 예외로 취급하면 안 된다. 원시 캐시를 수정하지 않고 집계 단계에서 불일치를 거부한다.

## 5. 문서와 해석 범위 대조

보고서 템플릿에서 단일 조건, 동일 가중 확률 평균, 실제 1,200명의 투표가 아님, 현재 전국민 추정이 아님, 연도 차이를 사회 변화로 해석할 수 없음, 교란요인을 보정하지 않은 성별·연령별 기술 통계, 정확도·불확실성 미산출, 의견 미수집을 명시한 것을 확인했다. 원자료 개인별 응답을 보고서에 싣는 경로는 없다.

현재 판정은 **완료 전 코드 검토**다. 실제 1,200명 완료, 최종 캐시 정합성, 도구 호출 상태, 실행 메타데이터 누락 수, 실제 생성 보고서의 수치 대조는 아직 이 감사에서 확인하지 않았다. R1/R2 수정 및 최종 캐시 검증 후 아래에 증거를 추가한다. 기존 방법론 이슈나 정확도 게이트를 VERIFIED로 변경하지 않는다.

## 6. 후속 검증

### 6.1 R1/R2 수정 확인

- R1: 실제 집계 코드의 토큰 계산 구문을 추출해 `usage=null` 입력을 검사했다. 예외 없이 토큰 0으로 처리했다. 실제 완료 캐시의 사용량 누락은 0건이다.
- R2: 실제 집계 코드의 캐시 검증 루프를 추출해 유효 응답의 model, cache_key, wave를 각각 불일치시켰다. 세 경우 모두 AssertionError로 거부했다. 현재 문항·프로필로 재생성한 프롬프트 해시와 runtime model/provider, 금지 item·reroute 검사도 소스 및 최종 캐시에서 확인했다.
- 이전 3~5절의 발견사항과 완료 전 판단은 당시 기록으로 보존한다. R1/R2는 이번 확인으로 해소했다.

### 6.3 최종 판정

현재 산출물의 캐시 정합성과 기술 집계에 미해결 오류는 발견하지 못했다. 실행 완료 및 보고서 산출은 이 범위에서 통과한다. 초기 108건의 runtime 미기록, 전역 AGENTS 포함, 불변 모델 스냅샷 미확보, 단일 조건·단회 실행·실측 정답 부재는 보고서에 유지된 제한이다. 현재 국민 대표성, 정확도, 반복 안정성, 조건 민감도 또는 다른 방법론 게이트를 검증했다는 판정으로 확장하지 않는다. 계정 사용량 0%→2%는 보고서가 계정 전체 변화로 구분하며, 이 감사는 계정 서비스 측정을 독립 재현하지 않았다.
