## §1. 명칭과 한계 — 홀드아웃이 아니다

### 1.1 누가 무엇을 아는가

## §3. 동결 커밋 절차 (서명 전 확인과 서명 후 확인을 나눈다 — Codex #22)

**A. 서명 전 확인** — 각 항목은 **정상 경로의 증거 또는 등록된 폴백의 증거** 중 하나로 충족해야 한다(v2, N10). 둘 다 없으면 서명하지 않고 §9 마감 규칙을 따른다.
1. **M-01~M-24**: 각 항목이 값·해시로 채워져 있거나, 그 항목에 등록된 폴백 증거가 있다. 선택 스위치는 포함/제외 값으로 확정돼 있다. 등록된 폴백은 다음 두 가지다.
   - **M-16 G9**: 산출된 기준선 파일 해시, 미산출 목록과 사유 증거, `S1 = 미검정(G9 미산출)` 값, G9 코드·골든 해시(01 §5.3). 4종 파일이 모두 있을 필요는 없다.
   - **M-17 EXP-013**: 승인 판본의 해시, 또는 §8.1 자동 폴백(I0) 적용 기록.
2. **교차검토**: Codex 교차검토 AUDIT가 있고, `AGENTS.md:46`의 재검토 조건을 충족했다. `AGENTS.md:46`과 `ISS-026:26`의 문구가 충돌한다(3회차를 재량으로 둘지). 이에 대해 **인간이 해소한 기록**이 있어야 한다. 그 기록 없이 에이전트가 한쪽 해석을 골라 충족으로 표시하지 않는다(N15).
3. T4 최소판, G9 코드, 러너에 대해 설계 감사·결과 감사·Codex 검토를 마쳤다(`AGENTS.md:43-46`).
4. 개발셋 리허설이 실행 정합성 기준(§8.3)을 통과했다.
5. **추론 모의**: 모의 EXP를 완료했고 합격했다. 또는 불합격이거나 미완료라서 P1·S1이 `미검정(추론 부적합/미검증)`으로 매니페스트에 등록됐다(01 §4.1, D48).
6. **비용**: 비용 게이트와 §6의 누적 비용 가드를 통과했다(EXP-018 §비용, N14).
7. 해시를 동결 직전에 다시 계산해 일치를 확인했다.
8. **실행 방식**: Batch로 실행한다. 동기로 실행하려면 ISS-036 경로 (가) 또는 (나)의 완료 기록(인간 기명, 커밋 해시)이 있어야 한다(N9). 그 기록이 없으면 동기 실행은 금지다. Batch도 쓸 수 없으면 **중단**한다. 동기로 자동 대체하지 않는다.
9. **W10 비의존(N1)**: W10(사전등록 03)의 산출물은 W11 C0 서명의 선행조건이 **아니다**. W10은 03 §5.1(D38)의 단계별 후속 동결을 따른다. 다운로드 전에는 존재할 수 없는 W10 산출물(W-05 실제 파일 해시, 격리 검증 로그, 보정 풀 모의)은 여기서 요구하지 않는다. W11 결과 보고에는 "W10은 별도 동결, 상태 = ○○"라고 명시한다.

## §4. 정답 파일 비열람 규칙과 증거

### 4.1 금지와 허용
- **금지 기간**: C1의 외부 확정(§4.2) 전까지.
- **금지 행위**:
  - 9회 지선 개표 파일(선관위 파일데이터, OpenAPI, 선거통계시스템 개표 화면)의 다운로드·열람
  - registry에 9회 지선 항목 추가
  - 결과 수치를 설계 문서에 인용
- **허용**:
  - 파일 식별 메타데이터 확인. 노출이 생기면 기록한다.
  - 과거 선거(8회 지선, 20·21대 대선) 자료의 다운로드·등록

### 4.2 증거 사슬 — C1도 정답 다운로드 전에 외부 확정한다(Codex 종합)
1. **C0 동결 커밋**: 태그, push, 외부 타임스탬프(§3).
2. **C1 생성 산출**:
   - raw jsonl sha256, 생성 실행 ID(G-n), usage 합계를 커밋하고 push한다.
   - 같은 해시를 **외부 타임스탬프로 확정**한다. C0의 타임스탬프만으로는 "생성이 정답 다운로드보다 앞섰다"는 사실을 증명할 수 없기 때문이다.
3. **C2 정답 등록**:
   - C1 외부 확정 **이후**에 다운로드한다.
   - registry에 path, sha256, `election_date: 2026-06-03`, `downloaded_at`, 출처를 적는다.
   - **다운로드·접근 기록**(브라우저 다운로드 기록 사본, 파일 생성 시각, 다운로드 담당자)을 별도 파일로 보존한다.
4. **C3 평가**: 평가 사건 로그(§5)를 먼저 기록한 뒤 채점한다. 리포트에는 C0 해시와 평가 사건 번호를 적는다(`ISS-009:25`).

**검증 방법**
- `git log --diff-filter=A -- <지선 파일 경로>`와 `git log -S "<지선 sha256>" -- data/registry.json`의 최초 커밋이 C1 **이후**인지 본다.
- 외부 타임스탬프 순서가 C0 < C1 < C2 `downloaded_at`인지 본다.

**한계 [약~중]**
- git 작성 시각과 파일 생성 시각은 조작할 수 있다.
- "열람하지 않았다"는 최종적으로 자기 신고다. 매니페스트에 아래 선언문을 넣는다.
  > "서명자는 C1 외부 확정 시점까지 9회 지선 개표 파일과 선관위 개표 수치를 열람하지 않았다. 보도로 접한 결과 정보: [있음/없음 — 범위]."

### 4.3 후보 정보 수집 (노출 최소화)
- **자료원**: 선관위 공식 후보자 정보(후보자 명부, 선거공보)만 쓴다. 제공 화면은 `[미확인]`. 개표 화면과 당선인 화면은 열지 않는다.
- **노출 기록**: 후보자 화면에 당선 표시가 함께 보일 수 있다 [추측]. 보이면 M-06 수집 기록에 "당선 표시 노출: 예/아니오"를 적는다.

## §5. 평가 사건 로그와 "시도"의 정의 (Codex #7, #25)

### 5.1 세 종류의 ID

| 종류 | ID | 무엇 | 예 |
|---|---|---|---|
| 생성 실행 | G-n | 봉인 요청 파일로 모델을 호출한 실행 1회. 성공·실패·미완료를 가리지 않는다 | G-1 본 실행, G-2 재실행 |
| config 개정 | R-n | 매니페스트 항목의 변경(모델·요청·뱅크·채점 규칙·후보 정보 등). R-0 = C0 | R-1 모델 EOL로 폴백 모델 지정 |
| **평가 사건** | **E-n** | **정답과 예측을 결합해 본 모든 행위**. 단위·지표·목적(판정·기술·진단·그림·수동 점검)을 가리지 않는다 | E-1 본 채점. 한 선거 오차만 먼저 본 것도 E |

### 5.2 로그 규칙
- **추가만 한다**(append-only). 형식은 JSONL이며 저장소에 커밋한다. 파일명 제안: `docs/6_백테스트/봉인_평가사건로그_9회지선.jsonl`.
- **E 항목은 사전 기록과 사후 기록 두 줄**이다.
  - 사전 기록(행위 전): 일시, 수행자, 목적, 입력 해시(예측 파일, 정답 파일, 채점기), 볼 단위·지표.
  - 사후 기록(행위 후): 실제로 본 출력의 범위, 산출물 해시.
- **첫 판정은 E-1이다.** E-1은 동결 config 그대로 P1·S1과 모든 사전등록 기술 지표를 **한꺼번에** 산출한다. E-1 전에 정답을 결합해 보는 행위는 금지다. 예외는 기계적 어댑터 검증(골든 테스트: 합계 대조)뿐이며, 이것도 E-0으로 기록한다.
- **E-1 뒤의 모든 E는 추가 평가 사건이다.** 번호를 매기고 모두 보고한다. 헤드라인은 E-1이다(01 §6.3).
- **R-n이 E-1 뒤에 생기면** 그 뒤의 E는 "수정 후 평가"로 표기한다. E-1 결과를 지우거나 대체하지 않는다.

### 5.3 생성 결과 채택 규칙 (선별 금지)
- **스모크**: 개발셋(21대 대선) 요청으로만 한다. 봉인 요청으로 스모크하지 않는다. 스모크 응답은 어떤 봉인 산출에도 쓰지 않는다.
- **본 실행**: 봉인 요청 파일로 하는 생성은 G-1이 기본이다.
  - G-1이 §6의 무효 조건에 걸리면 G-2를 실행한다. 이때 모델이 바뀌면 R-n도 함께 생긴다.
  - **어느 G를 쓸지는 규칙으로 정한다**: 무효가 아닌 첫 G. 내용을 보고 고르지 않는다.
- **요청별 응답**: 처음 받은 **유효** 응답을 채택한다. 같은 request_id에 여러 응답이 있어도 모두 보존하되 쓰지 않는다.
- **재호출 200명 응답**은 본 응답을 대체하지 않는다(기술 전용).
- **보존**: 실패 응답, 미완료 실행, 무효 실행의 원문과 로그를 **삭제하지 않는다**.

### 5.4 수정한 v0 규칙
v0 §6에는 "모델 EOL 시 시도 증가"라고 적었다. v1에서는 모델 교체를 **config 개정 R-n**으로 적는다. "시도"(평가 사건) 번호는 정답을 결합해 볼 때만 증가한다. v0의 정의 불일치(Codex #7)를 이렇게 해소했다.

**동결 후 기계적 어댑터 변경**(E 번호를 증가시키지 않는 유일한 변경)은 아래 세 조건을 모두 만족해야 한다.
- (i) 로더의 열 이름·인코딩·행 유형 **화이트리스트 추가**다(01 §2.2 중단 후 인간 분류).
- (ii) 지표·집계 식과 후보 화이트리스트를 바꾸지 않는다.
- (iii) 골든 테스트(시도 합 = 공표 유효투표수, `ISS-037:322` 취지)를 통과하고 diff를 공개한다.

이 변경은 R-n으로 기록하고, E-1 **전에** 끝낸다.

## §7. 라벨·컷오프 규칙 (Codex #21, #25)

**필드와 정밀도**
- `model_cutoff_month`: YYYY-MM. 비공개 모델은 학습 컷오프, 오픈모델은 웨이트 릴리스 월(`ISS-012-모델컷오프-오염게이트.md:13`)이다.
- `election_date`: YYYY-MM-DD.
- 비교는 **월 단위**로 한다. 컷오프 월 전체를 학습 범위로 보는 보수 해석을 쓴다: `model_cutoff_month < election_date[:7]`. 이는 `llm_client.py`의 `ELECTION_YM` 방식과 같다.

**성과 판정 규칙**

| 상태 | 조건 | 효과 |
|---|---|---|
| 정상 | `model_cutoff_month < 2026-06` **그리고** 근거가 1차 출처 | 판정 가능 |
| `MEMORIZATION_RISK` | `model_cutoff_month ≥ 2026-06` | 성과 인용 금지(`ISS-012:13`) |
| `판정 불가(컷오프 미상)` | 컷오프가 없거나 근거가 1차 출처가 아님 | **일관되게 성과 판정 불가**. 봉인 config에서는 이런 모델을 고를 수 없다 |
| `PRE_ELECTION_KNOWLEDGE_RISK`(제안) | 2025-06 ≤ `model_cutoff_month` < 2026-06 | 선거 전 판세를 학습했을 수 있고 개발셋 연속성도 깨진다. 성과 인용 전 인간 판단 [중] |

**폴백 모델**
- ISS-012 결정 3의 문언대로 `model_cutoff_month < 2025-06`(`ISS-012:15`)이다.
- v0의 "< 2025-06-03은 같은 기준"이라는 서술은 틀렸으므로 철회한다.
- 폴백은 **정확한 스냅샷 ID를 R-n으로 새로 동결**해야 한다.

**1콜 프로브의 범위**
- 프로브는 **그 시점의 가용성 증거일 뿐**이다.
- 이후의 가용성, Batch 지원, 컷오프를 증명하지 않는다. 컷오프는 1차 문서 근거로 따로 적는다.

**게이트 구현**
- 생성 단계 상수 `ELECTION_DATE = "2025-06-03"`(`llm_client.py:21-22`)은 지선에 대해 더 엄격하게 작동한다(`ISS-038:84`).
- 채점 단계 게이트는 없다(fail-open, `ISS-037` #3). T4 최소판은 registry `election_date` × EXP 카드 `model_cutoff_month`로 assert해야 하고, 필드가 없으면 UNKNOWN(판정 불가)으로 **fail-closed** 처리한다.
- 러너는 `assert_cutoff`를 반드시 거친다.

**메타데이터와 차단 상태의 구분**: 평가 사건 번호는 중립 메타데이터다. 차단 상태는 위 표와 01 §6.3에 있다.

## §8. EXP-013 결과 → 봉인 config 완전 선택표 (Codex #5)

### 8.1 판본 고정
- **참조 대상**: 이 선택표가 참조하는 것은 **인간이 승인한 EXP-013 판본**이다. 승인 시점의 커밋 해시와 파일 sha256을 M-17에 기록한다.
- **현황(참고)**: 2026-09-24 현재 EXP-013은 v1.3 초안이다(Codex 2회차 반영, 미승인). v1에 적었던 sha256 `32cb352d…`는 개정 중에 잰 값이라 참조하지 않는다. 승인된 판본의 해시는 승인 시점에 M-17에 새로 기록한다.
- **재승인 조건**: 승인 판본의 대비 이름·판정 범주가 아래 입력과 다르면 선택표를 다시 승인해야 한다. 이 재승인은 **EXP-013 결과를 보기 전에** 끝내야 한다 `[D32]`.
- **자동 폴백 조건**: EXP-013 결과가 나오기 전에 선택표가 승인되지 않으면 이 선택표는 쓸 수 없고, §8.2의 폴백(I0)이 **자동 적용**된다. 결과를 본 뒤에 선택 규칙을 만들 수는 없다.

### 8.2 입력·함수·출력

**입력.** 승인된 EXP-013 판본의 사전 지정 판정 결과만 쓴다.

| 입력 | 출처(EXP-013 v1.2/1.3 명칭) | 가능한 상태 |
|---|---|---|
| A1 | F-H2 ΔMAE(I1−I0) | 개선(Holm 유의·점추정<0, 후보 상쇄 경고 없음) / 개선(후보 상쇄 경고) / 차이 증거 없음(비유의) / 악화(Holm 유의·점추정>0) / 미결(결측 과다) / 미실행 |
| A2 | F-H2 ΔMAE(I2−I0) | 위와 같음 |
| B1 | H2b(I1 수준, EXP-013 v1.3 "발췌 순서 민감성") | 동등(요구 검정력 충족) / 동등 관측(검정력 미달 — **게이트 통과 아님**, EXP-013 v1.3) / 실질 차이 / 미결 / 미실행 |
| B2 | H2b(I2 수준) | 위와 같음 |

**입력이 아닌 것**(결과가 어떻든 선택에 쓰지 않는다):
- F-H1(살 사다리): 봉인 런은 KGSS 살이 없는 뱅크 카드를 쓴다.

### 8.3 개발셋 리허설 — 실행 정합성과 성능의 구분 (Codex #5)
- **대상**: 21대 대선(개발셋). 선택표가 낸 봉인 config와 같은 템플릿을 쓰고, 선거 슬롯만 대선으로 바꾼다. 별도 EXP 카드가 필요하다 `[D15]`.
- **실행 정합성(통과·실패 판정)**. 아래가 **모두** 참이어야 통과한다.
  - (i) 요청 파일을 다시 물질화하면 같은 sha256이 나온다.
  - (ii) 모든 요청이 완료되고, 재시도 후 유효 응답률이 98% 이상이다.
  - (iii) 응답 model이 요청 model과 모두 일치한다.
  - (iv) 채점기 골든 테스트(전국 34,980,616표, `ISS-037:322`)를 통과하고, P1·S1·모든 기술 지표 필드를 끝까지 산출한다.
  - (v) 컷오프 음성 테스트(미상·이후 모델 → 판정 불가·MEMORIZATION_RISK)를 통과한다.
  - (vi) 실측 토큰으로 비용 게이트를 다시 계산했다.
  - 실패하면 파이프라인을 고쳐(R-n) 리허설을 다시 한다.
- **성능(기술)**: 개발셋 M̄, 증분, 기술 지표를 보고한다. 대외 인용은 할 수 없다.
  - **리허설 성능으로 config를 바꾸지 않는다.** 선택표 결과를 뒤집을 수 없다.
  - v2(N2): 리허설 성능을 보고 config를 바꾸는 일은 **이 선택표의 출력이 아니다.** 인간 재승인만으로 바꾸는 통로(v1)는 삭제했다. 꼭 바꿔야 한다면 **별도 사전등록 개정**으로만 가능하다(새 판본, Codex 교차검토, 인간 기명). 이때 원래 선택과 변경 이유를 보존하고, 결과 보고에 "개발셋 성능 열람 후 개정"임을 명시한다. 이 개정이 동결 전에 끝나지 않으면 원래 선택표의 출력을 그대로 쓴다.
