- 상태: **집계·핵심 흐름·저장 표시 검증 통과 — 실제 브라우저 QA 미실시**
- 범위: `민심테스트/web/dist/app.js`, `research.js`, `research-data.js`, `style.css`, `index.html`
- 웹 checkout은 수정하지 않았다. Sites 도구 및 브라우저는 사용하지 않았다. JS 실행은 로컬 DOM 대역을 사용했으므로 실제 브라우저의 시각·레이아웃·접근성 검증을 뜻하지 않는다.

## 1. 착수 전 설계 감사

실행된 시뮬레이션과 화면 시연용 예시를 별도 데이터·결과 컴포넌트로 표시하는 설계를 검토했다. 실제 여론이나 검증된 정확도로 오인시키지 않도록 숫자 인근에 모델·과거 응답자 수·확률평균·예측오차 및 대표성 미검증을 유지한다. 가사분담의 기존 익명 A/B 실험은 성별 고정 GPT-5.5 조건과 다른 별도 기록으로 표시한다. 웹에는 집계만 복사하고 개인 raw·PID·원문은 포함하지 않는다.

## 3. 로컬 DOM 대역 흐름 검사

실제 app/research 소스를 JS VM에 로드하여 렌더 문자열과 등록된 이벤트 핸들러를 검사했다. 네트워크나 브라우저 도구는 사용하지 않았다.

- 홈 연구 카드 정확히2개; 연구 문항의 result/predict 직링크4개 모두 예측 양식을 우회하고 실제 집계 컴포넌트를 렌더했다.
- 연구 결과에는 데모 score-strip/range-note/visitor-chart가 없고 로컬 의견 버튼은6개였다.
- H30와 E에 서로 다른 의견을 저장한 뒤 각각 유지됐으며, 새 VM에서 localStorage를 복원해도 저장 질문과 조건별 의견이 유지됐다.
- 연구 링크 복사는 result URL을 생성했다. 저장 화면에서 연구 카드가 다시 렌더됐다.
- 기존 데모 AI 직링크는 미예측 상태에서 양식을 표시하고,60을 제출하면 기존61 기준98점을 표시했다.

## 4. 발견사항

### R1 — 가사 비율 기준 설명 [초기 판단 정정, 블로커 아님]

초기 검토에서 '남편의 몫이 접힌 문구에만 표시된다'고 지적했으나, research-data.js의 선택지는 이미 '남편 약25%' 등 남편을 명시하고 있었다. 따라서 숨겨진 기준이라는 초기 판단은 부정확했고 블로커에서 제외한다. 부모 에이전트가 추가한 '선택지의 가사 비율은 남편 A가 맡는 몫입니다.' 및 의견 선택의 '남편 A가 맡을 가사 비율'은 설명 보강이다. 데이터의 기존 남편 표시와 추가 문구를 재확인했다.

### R2 — 저장 후 연구 카드/버튼 문자가 갱신되지 않음 [P2, 해결]

`app.js`의 save 이벤트는 saved class와 aria-pressed만 변경한다. 연구 카드가 SVG 대신 문자☆를 쓰고 연구 결과 버튼은 '☆ 저장'이라는 문자를 쓰므로, 클릭 후 state.saved=true·aria-pressed=true인데도 보이는 문자가 이전 상태에 남는다. 실제 핸들러의 DOM 대역 실행에서 재현했다. 연구 카드의★/☆, 결과의 '★ 저장됨'/'☆ 저장'을 상태와 함께 동기화해야 한다.

## 5. 판정 범위

집계값·주요 라우트·조건별 의견·저장 복원·링크·기존 예측 흐름은 위 범위에서 통과했다. 실제 브라우저에서의 모바일 레이아웃·초점 표시·스크린리더·배포 URL 동작은 확인하지 않았고, 미리보기 실행이 차단됐다는 부모 에이전트의 상황 보고와 별개로 이 감사는 소스 및 DOM 대역 검사만 수행했다.

## 6. 표시 변경 후 독립 재확인

- 현재 save 분기를 실제 소스에서 추출해 카드·결과버튼을 각각 저장/해제했다. 카드 문자는★/☆, 결과버튼은 '★ 저장됨'/'☆ 저장'으로 상태 및 aria-pressed와 함께 바뀌었다. R2 해소.
- 가사 연구 결과 렌더 문자열에 남편 A의 몫이라는 상시 설명과 의견 선택 안내가 포함된 것을 확인했다. R1의 부정확한 초기 판단은 위에 정정했다.
- 현재 검토 범위에서 미해결 기능·수치 오류는 발견하지 못했다. 실제 브라우저 QA, 모바일 시각 검증 또는 배포 성공을 확인했다는 의미는 아니다. 웹 파일을 직접 수정하지 않았다.
